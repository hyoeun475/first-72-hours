# First 72 Hours 프로젝트 작업 원칙

## 작업 전
- `../FIRST_72_HOURS_MVP_SPEC_통합본.md`(상위 폴더)를 먼저 읽는다.
- 기존 저장소 구조와 기술 스택을 확인하고 불필요하게 덮어쓰지 않는다.
- 요구사항이 충돌하거나 불명확하면 피해자 안전과 개인정보 최소화에 유리한 선택을 한다.

## 피해자 안전
- 피해자를 비난하거나 책임을 묻는 표현을 사용하지 않는다.
- 신고, 가족 공개, 가해자와의 관계 단절 등을 강요하지 않는다.
- 즉각적인 신체 위험이 있으면 일반 기능보다 긴급 도움 안내를 우선한다.
- 72시간을 법적 신고 기한이나 지원 마감으로 표현하지 않는다.
- 가해자와 직접 대면하거나 협박에 응답하도록 권하지 않는다.

## 개인정보 및 데이터
- 실제 성적 이미지·영상·음성 파일 업로드 기능을 만들지 않는다.
- 사건 메모, URL, 계정명 등 민감정보를 로그나 분석 도구에 남기지 않는다.
- 명시적 동의와 보안 검토 없이 서버, 외부 AI API, 제3자 서비스로 사건 정보를 전송하지 않는다.
- 저장 기능을 추가할 때는 저장 범위·위험·삭제 방법을 사용자에게 알린다.
- 이용자가 기록을 수정·삭제·내보낼 수 있도록 한다.

## 에이전트 응답
- 사용자가 제공하지 않은 사실을 추측하거나 만들어내지 않는다.
- 모르는 정보는 '확인 필요'로 표시한다.
- 법률적 결론, 죄명, 유죄 여부, 수사 결과를 단정하지 않는다.
- 기관 연락처와 제도는 공식 출처로 확인된 데이터만 사용한다.
- AI가 생성한 사건 정리는 참고 초안임을 명시한다.

## 구현 및 검증
- MVP는 규칙 기반 흐름과 템플릿을 우선한다.
- 외부 MCP나 LLM API를 추가하기 전에 실제 필요성과 데이터 노출 위험을 검토한다.
- 기능을 추가할 때 관련 테스트를 함께 작성한다.
- 작업 후 lint, typecheck, test, build를 실행한다.
- README에 실행법, 데이터 처리 방식, 알려진 한계를 기록한다.
